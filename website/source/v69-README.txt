V69: Player-request-driven EPG queue (best-effort, no cron)
An authenticated xmltv.php request immediately returns the last completed compressed EPG or existing provider fallback. On PHP-FPM hosts supporting fastcgi_finish_request(), the request then starts or advances one EPG source in the persistent v68 build queue, behind a per-workspace lock. Repeated player requests advance remaining sources and eventually publish the merged EPG. The old completed guide stays available while a new one builds. Refresh interval uses epg_minutes (default 720 minutes).
IMPORTANT: This is request-driven, not a true autonomous background scheduler. A single EPG request cannot guarantee finishing all sources, and some shared hosting providers terminate PHP after the response. Without PHP-FPM fastcgi_finish_request(), automatic request-triggered steps are intentionally disabled rather than blocking the IPTV player. Use the dashboard build for guaranteed progress, or an actual scheduler for fully unattended completion. Preserve storage/ during installation.
